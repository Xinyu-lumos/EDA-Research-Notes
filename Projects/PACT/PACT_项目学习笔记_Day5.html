01今天要回答：候选如何组成搜索

第 4 天看到技能产出 DCP。今天看代理怎样把候选存成谱系，何时提升全局最佳，怎样保留可继续探索的 beam，以及在预算和中断之间保持一致。

图：记录身份

节点绑定候选 ID、父节点、DCP 路径与哈希，以及集中测量。

best：当前成绩

一次提交事务中，满足门槛的兄弟候选至多一个晋升。

beam：探索余地

保留有限个可选种子；不等于最终结果，也不自动轮流执行。

读图：箭头只表示 parent_candidate_id；每个节点还有文件哈希和测量元数据。

源码：candidate_graph.py · L1；candidate_graph.py · L60；candidate_graph.py · L194；candidate_graph.py · L244。

02候选图保存什么

图由 nodes、root_candidate_id、current_best_candidate_id、beam_candidate_ids 和顺序分配器构成。根固定为 c000000；子节点要求父节点存在且深度恰好加一。节点的 DCP 哈希用于校验文件身份，artifact_state 管理文件状态，search_state 管理搜索资格。

读图：搜索状态被剪枝，并不立即等于 DCP 文件被删除。

两个容易混淆的状态current_best_candidate_id 指当前全局最佳；beam_candidate_ids 是当前可探索的有限集合。全局最佳会被 beam 保留，但 beam 还可能有非最佳节点。另有独立的 enabling pool，保留满足规则的非提升候选作有限后续组合。

源码：candidate_graph.py · L34；candidate_graph.py · L60；candidate_graph.py · L194；candidate_graph.py · L223；memory.py · L1027。

03全局最佳怎样晋升

select_atomic_promotion_candidate() 先检查每个兄弟候选的集中测量 eligible_for_beam 与 Fmax，再要求 Fmax 严格高于原全局最佳加配置门槛。满足条件的候选按最高 Fmax 选出至多一个；并列按兄弟顺序确定。当前配置门槛是 0.01 MHz。

读图：示例数据为教学构造。高 Fmax 若不合格不能晋升；刚好等于门槛也不能晋升。

提交时代理逐个验证规范候选 DCP 是否存在、哈希是否吻合、测量是否齐全，写入图和历史，然后更新 beam。技能自己的局部 WNS 观测不能替代这里的集中测量。未晋升的候选仍可能进入 beam；accepted 历史字段记录是否晋升，而不是是否产生候选。

源码：agent.py · L5754；agent.py · L5780；agent.py · L5900；config.yaml · L90。

04beam 为什么不是“WNS 前三名”

beam 的 Pareto 目标明确写在源码里：最大化集中测量 Fmax、最小化谱系累计运行时间。只有测量完整、文件已物化、可用于 beam 且有数值 Fmax 的 active 节点参与。这里的谱系耗时只是搜索启发式，不能当成竞赛真实增量耗时。

读图：A 的 Fmax 高于 C 且耗时更短，因此 A 支配 C。B 更快但更耗时，与 A 均在第一前沿。

默认 beam 宽度为 3。剪枝时先钉住当前全局最佳；若宽度允许，可为最近创建且尚未消费的一次 continuation 留一个位置；剩余位置按 Pareto 前沿补齐。当前沿超出名额时，优先尝试可用的物理签名多样性，否则用拥挤距离排序。保留集只决定可选种子，LLM 选择种子，Python 不自动轮换。

源码：candidate_graph.py · L270；candidate_graph.py · L633；memory.py · L2297；config.yaml · L92。

05怎样选择下一轮的起点

默认种子是当前全局最佳。显式指定时，种子必须仍有物化 DCP、可用于 beam，并属于 active beam 或 active enabling pool。若文件不存在，验证会把节点标为 missing、撤出可选集合。

读图：第二行是条件性保留，不保证每轮都有。若 beam 宽度为 1，无法同时保留不同的 continuation。

被 beam 剪枝的节点仍留在 nodes，其搜索状态改成 pruned；有独立的产物回收逻辑。回收会保护根、全局最佳、beam、enabling pool 和待完成事务等，删除非保护且不可选的候选 DCP 后，图节点仍保留删除记录。

源码：memory.py · L1027；candidate_graph.py · L633；artifacts.py · L150；artifacts.py · L267。

06预算限制的是哪一层

默认总时限 3600 秒，动作阶段保留 480 秒收尾；execute_with_run_deadline 使用剩余时间减去这段保留时间。配置还给相应候选执行安排 120 秒提交预留。token 预算默认 1 美元，Memory 分别追踪花费和剩余；它与运行时间不是同一个计数器。

读图：图按运行刚开始时估算；实际剩余时间随时钟流逝，执行入口会重新计算。120 秒预留不能机械地视为所有动作的统一净窗口。

配置里的 max_rounds: 8 注释明确指出，在当前 staged ReAct 模式下它不构成主决策循环的硬上限。停止还受实际时限、成本与动作可行性约束；评分预测和饱和信息供决策参考，不自行授权执行。

源码：config.yaml · L22；config.yaml · L72；config.yaml · L88；memory.py · L275；memory.py · L2075；agent.py · L6848。

07“记忆”与事务怎样持久化

Memory.save() 通过原子 JSON 写入保存预算、历史、候选图、当前遥测、待处理事务等。图节点持有 DCP 路径与哈希；JSON 本身不包含设计电路。提交一个已测量动作时，先在内存副本中建立所有兄弟节点、选晋升者并修剪 beam，最后一次写回 memory.json。

读图：状态 JSON 可以重读；物理候选仍依赖实际 DCP 文件存在并通过哈希校验。

中断恢复按事务阶段处理：prepared/executing 的动作不会假装已经产生可用候选；publishing 校验并补齐规范文件；published 补做缺失的集中测量；measured 才进入提交。若发现只有部分兄弟节点已经进图，会报错，不静默拼接历史。

源码：memory.py · L202；agent.py · L5780；agent.py · L6153；agent.py · L6282；agent.py · L6396。

08断点续跑到底恢复什么

传入 --resume 时，必须已有 memory.json。入口核对运行模式、根候选、输入 DCP 与根 DCP 的哈希；严格提交模式还限制时限和输出路径变更。随后恢复待处理事务，核对最佳候选的文件和哈希，并重建 current_best.dcp 与输出。

读图：恢复不是简单重读 JSON。若根或 best 的 placed_legal 不是 True，当前分支会对它们进行集中重测；随后尝试重新采集 best 的分析遥测。

读源码时保留一个边界当前主恢复路径的“placement 重新测量”条件检查的是根与 best；候选图里另有 resume_constraint_refresh_candidate_ids() 辅助函数，用于找旧节点缺少约束证明的情况，但本轮检索未发现主入口调用它。不能把辅助函数的意图直接写成每次 resume 都执行的保证。

源码：agent.py · L6621；agent.py · L6871；agent.py · L6925；agent.py · L6987；candidate_graph.py · L584。

09算例、练习和自测

以下是人为构造的纯函数算例，只演示 Pareto 判断。它不打开 Vivado、不生成 DCP，也不测试完整提交和断点恢复。

练习 A：运行候选比较 · 20 分钟

在仓库根目录的 PowerShell 中粘贴整段命令。-B 避免产生字节码缓存；练习不会创建 DCP。

@'
from FDAgents.candidate_graph import dominates, pareto_fronts

def node(cid, fmax, runtime):
    return dict(candidate_id=cid, fmax_mhz=fmax,
                cumulative_lineage_runtime_s=runtime,
                eligible_for_beam=True, measurement_complete=True,
                artifact_state="materialized", search_state="active")

a = node("c000001", 180.0, 100.0)
b = node("c000002", 185.0, 150.0)
c = node("c000003", 178.0, 180.0)
print(dominates(a, c))
print([[n["candidate_id"] for n in front]
       for front in pareto_fronts([a, b, c])])
'@ | python -B -

预期输出：

True
[['c000001', 'c000002'], ['c000003']]

把 B 的 Fmax 改为 179，耗时仍为 150 秒，再猜前沿。修改 C 的 search_state 为 pruned，观察它是否还能出现在前沿列表里。

合上正文，做六道自测

候选 DCP 的局部 after_wns 能直接决定晋升吗？

不能。晋升依据规范候选 DCP 的集中测量、资格和 Fmax 门槛。

比当前 best 刚好高 0.01 MHz 会晋升吗？

不会；当前函数要求严格大于 best + 配置门槛。

beam 只按 WNS 排序吗？

不是。核心 Pareto 目标是 Fmax 与谱系累计耗时；剪枝还钉住 best、可能保护 continuation，并在拥挤前沿考虑物理多样性。

pruned 节点会立即从图和磁盘同时消失吗？

不会。节点仍留在图里；独立回收逻辑可在保护条件之外删除不可选 DCP，并记录 artifact_state。

resume 是否无条件重测所有 beam 节点？

不是。当前主路径在根或 best 缺少 placed_legal True 时重测这两个节点，并尝试刷新当前 best 的分析遥测。

memory.json 存着完整候选设计吗？

不存。它记录状态、文件路径与哈希；实际电路在候选 DCP 中。
