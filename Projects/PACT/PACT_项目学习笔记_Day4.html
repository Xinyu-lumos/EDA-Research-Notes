01今天研究：动作怎样产出候选

第 3 天停在“从菜单选出并绑定动作”。今天把操作卡片交给具体技能，看它如何修改设计、保存 DCP，再把候选交回代理测量。

phys_opt

固定预设驱动 Vivado，先看最短的执行路径。

局部重布线

围绕少量关键网构造候选，理解同一起点的比较。

LUT 引脚交换

改变物理输入映射，理解两个后端如何分工。

本课的“技能”是 FDAgents/skills/ 下的 Python 实现。它们通过注册表和约定的 execute 接口协作，并不必须继承某个统一的 BaseSkill 类。

读图：箭头表示执行与结果交接。技能内观测和集中测量要分开理解。

今日验收能说明每个技能“改了什么、从哪份 DCP 开始、返回哪些候选、谁决定候选晋级”。建议用 90 分钟完成本课。

源码：__init__.py · L31；agent.py · L9513。

02共同接口：输入卡片，返回结果

代理从 SKILLS[skill_name] 取得实例，在本次动作的工作目录作用域内调用 execute(mcp, target, params, before_wns, clock_period)。输入既告诉技能“做什么”，也提供比较基线。

读图：上半部是调用输入，下半部是返回记录。路径指向产物；WNS 是技能当时观察到的数字。

看什么代码中的含义容易误读的地方
target / paramstarget 表示预设或目标；params 带入参数，框架还注入截止时间、候选上限等上下文。参数含义由具体技能解释。例如 phys_opt 的预设参数固定。
success技能认为本次执行已产出可用结果。不是“WNS 一定改善”，也不是最终接纳结论。
is_legal本课技能通常根据 route status 做局部布线判断。不等于完成布局、保持时间、脉宽等集中检查。
candidates显式的一组 SkillOutput，每项含 DCP、标签及可选证据/证明。不能只看 output_dcp 就认定这是全部待测输出。

candidate_outputs() 优先返回显式 candidates。没有显式列表时，只有成功、局部合法且提供 output_dcp，才包装为单个输出。这个方法不检查磁盘文件是否存在；文件检查在契约验证阶段进行。

源码：base.py · L24；base.py · L93；base.py · L107；agent.py · L9468。

03技能一：phys_opt 的固定预设

PhysOptSkill 是理解完整技能的最短入口。例如 target="Explore" 经固定表解析为 {"directive": "Explore"}，再调用 Vivado 的 phys_opt_design。

读图：这是正常成功路径。未知预设、额外参数或执行异常会返回失败。

先读三个细节

  1. 预设不能任意拼接。resolve_phys_opt_args 返回固定参数副本；未知 target 会失败。技能会拒绝允许集合以外的非内部参数。
  2. 命令操作当前 Vivado 设计。正常代理路径负责准备 seed。此技能的 execute 内没有先 open_checkpoint；单独调用时，不能以为传了 input_dcp 就会自动切换设计。
  3. 成功不要求 delta 为正。执行完成、局部布线检查通过并写出文件，就可能返回 success=True；收益仍由后续评价。
mcp_args = resolve_phys_opt_args("Explore")
# {"directive": "Explore"}

# 正常主线的教学摘录；省略异常、超时和检查代码。
await mcp.call_vivado("phys_opt_design", mcp_args)
after_wns = await mcp.get_wns()
# 接着读 report_route_status；检查通过才写出 DCP。

时序变化接近零时，代码会把相关 WARNING 加进摘要，帮助解释 no-op（没有明显变化）。没有收益与调用失败是不同的反馈。

源码：phys_opt.py · L21；phys_opt.py · L66；phys_opt.py · L113。

04技能二：围绕关键网重布线

对应实现为 CriticalNetRerouteSkill。先看默认 window 选择方式：从关键路径取数据引脚，组成小窗口，再在当前设计中把引脚解析成实际网。它还支持其他选择方式，本课先聚焦窗口机制。

读图：绿色线表示源与汇之间的连接。几何图不代表真实器件坐标或实测长度；新路径是否更快要重新测量。

窗口是候选集合的种子

路径引脚为 [u0/Q, u1/I0, u1/O, u2/D]，窗口大小取 2，会得到三个相邻窗口。代码会过滤不符合条件的引脚，对引脚和窗口去重；解析网时还有时钟网、扇出等限制。

[u0/Q,  u1/I0]
[       u1/I0,  u1/O]
[               u1/O,  u2/D]

一个窗口不一定对应两个网：两个引脚可能属于同一个网，也可能无法解析出有效目标。最终要看发现的网集合，并去除重复集合。

“局部”描述目标选择，不保证所有模式都只触碰这些网isolated_delay 对选定网 unroute 后定向重布线；默认 delay_group 还会运行 preserve / tns_cleanup；explore_group 则调用更广的 route_design -directive Explore。实际操作范围要看 route_mode 分支。

源码：critical_net_reroute.py · L58；critical_net_reroute.py · L199；critical_net_reroute.py · L587；critical_net_reroute.py · L699。

05每次尝试从哪里开始

局部重布线的候选循环在每次尝试前都会 open_checkpoint(input_dcp)。不同窗口通常成为同一 seed 的不同子候选，不会无意地把上次修改累积到下次。

读图：每行箭头表示“打开 seed 后执行本次修改”。上下三行是不同尝试，没有上下继承关系。

每次执行后读 WNS 与 route status，写出候选文件。局部合法输出加入 candidates，同时用局部 WNS 选一个 best 作为主结果。局部合法但比 seed 更差的候选，也可能被返回。最终由代理集中测量和评估。

预算耗尽时，保留已完成的部分

候选数量与剩余时间限制循环继续展开。candidate_budget_exhausted 检查框架提供的上限、截止时间和提交预留时间。因预算停止，不表示之前已经完成的候选全部失效。

阅读 details 时区分：attempts 是尝试反馈，candidates 是输出反馈，unstarted 是没开始的尝试。三者数量不一定相等。

源码：critical_net_reroute.py · L963；critical_net_reroute.py · L1079；critical_net_reroute.py · L1110；base.py · L163。

06技能三：LUT 引脚交换

LUT 的逻辑输入（如 I2）与 BEL 上的物理输入（如 A3）是两层概念。LutPinSwapSkill 用 RapidWright 改变逻辑输入使用的物理入口，再让 Vivado 恢复布线并评估时序。

读图：A3 → A6 是教学示意。实际可用引脚取决于目标 LUT、当前映射和后端解析。

后端 swap_lut_pins 调用 LUTTools.swapMultipleLutPins()，维护逻辑到物理的映射。设计意图是保持每个逻辑输入连接的网不变；这张示意图不代表额外做过形式等价证明。

FASTEST 是后端解析的别名：优先询问未映射输入，必要时按可用物理引脚顺序选择其他输入。不能硬编码理解为“永远 A6”，也不能凭这个名字推断全设计 WNS 一定改善。

读图：箭头表示文件交接。RapidWright 的编辑结果先落盘，Vivado 再加载、布线和测量。

自动扫描的一次尝试

  1. 从当前关键路径找 LUT 输入。auto 分支可预筛选候选，并受 max_cells、max_pins 等参数限制。
  2. RapidWright 读取当前轮起点。调用 swap_lut_pins，设置 unroute_affected=True，再写出交接 DCP。
  3. 逐个尝试布线预设。每个预设重新加载交接产物；Vivado route_design 后读取局部结果，保存候选。

源码：lut_pin_swap.py · L208；lut_pin_swap.py · L396；lut_pin_swap.py · L444；rapidwright_tools.py · L887；rapidwright_tools.py · L4075。

07同轮比较，跨轮继承

LUT 自动扫描与独立窗口不同：同轮尝试共享 current_dcp。当本轮最佳结果相对 current_wns 的改善严格大于 accept_min_delta，代码更新 current_dcp，再进入下一轮。这是逐轮累积的局部搜索。

读图：箭头表示起点更新。未超过阈值时不继续接受；accept_min_delta 默认 0.001 ns，菜单参数可能覆盖它。

实际返回列表，需要沿代码确认当前 auto 扫描分支只在 iteration == 1 时把局部合法输出加入显式 candidate_outputs。后续轮的胜出者可能成为主字段 output_dcp，但只要显式列表非空，candidate_outputs() 就优先返回那个列表。因此摘要里的“最终最好结果”不直接等于代理拿去测量的全部文件。

返回前，代码还会按局部 WNS 对显式输出应用数量上限。阅读时同时看 output_dcp、candidates 和 details.ancestry，不要只读摘要。

显式目标的串行编辑是另一分支。理解实际运行前，先确认 target 与 sweep_candidates，再沿对应路径追踪。

源码：lut_pin_swap.py · L540；lut_pin_swap.py · L564；lut_pin_swap.py · L594；lut_pin_swap.py · L621；base.py · L107。

08交回代理：文件合格，再集中测量

技能返回后，代理调用 validate_skill_outputs() 检查返回类型、候选数量、文件归属和证据边界。成功的 Python 返回值不能替代磁盘上的真实 DCP。

读图：箭头表示文件与身份交接。中央测量使用规范保存的候选文件，不直接沿用技能内 WNS。

看什么代码中的含义容易误读的地方
输出契约必须返回 SkillOutput；DCP 是普通文件、非符号链接，位于动作工作目录内，路径不重复。只构造 Path("x.dcp") 不表示文件存在，也不能返回目录外文件。
规范保存复制到候选目录 design.dcp，按预期 SHA-256 验证内容；有相应可读 EDIF 缓存时一起发布。这里规范的是位置与产物身份，不是重新综合设计。
集中测量measure_candidate 重开 DCP，重新查询时序、布局、路由与指定时钟。不会直接用 SkillResult.after_wns 或之前内存设计的旧结果。

读图：这是检查层次，不是逐项补救算法。必需观测缺失会影响测量完整性。

完整性、合法性满足后，eligible_for_beam 才可能为真；候选是否保留、晋级或成为最终输出，仍由候选图和提交逻辑决定。WNS 为负不必然失去继续优化的资格；setup 收敛程度与物理合法检查要分别读。

约束对比有条件。传入 reference_dcp_path 时，此函数会捕获并比较参考与候选的时钟、timing XDC。主候选循环所示调用未传该参数，不能仅因结果存在 constraint_identity_preserved 字段，就断言每次测量都在这里执行过两份文件的对比。

源码：base.py · L263；agent.py · L2557；agent.py · L9839；agent.py · L10071；measurement.py · L145；measurement.py · L238。

09算例、动手练习与自测

先用人为构造的数据复算指标，再运行纯函数练习。今天不启动 Vivado / RapidWright，不生成 DCP。

读图：数字为教学构造。点表示 WNS，横线表示距 0 的负裕量；正 delta 表示改善，仍需检查合法性。

练习 A：运行并解释 · 20 分钟

在仓库根目录的 PowerShell 中粘贴整段命令。-B 避免生成字节码缓存；这里只导入 Python 模块，不连接 FPGA 工具。

@'
from pathlib import Path
from FDAgents.skills.phys_opt import resolve_phys_opt_args
from FDAgents.skills.base import SkillResult, calculate_fmax
from FDAgents.skills.critical_net_reroute import _candidate_pin_windows

print(resolve_phys_opt_args("Explore"))
paths = [["u0/Q", "u1/I0", "u1/O", "u2/D"]]
print(_candidate_pin_windows(paths, window_size=2, max_candidates=3))

# 只构造数据对象；不创建 DCP，不代表文件契约已经通过。
r = SkillResult(
    success=True, before_wns=-1.0, after_wns=-1.1,
    delta_wns=-0.1, is_legal=True,
    output_dcp=Path("demo.dcp"), summary="teaching only",
)
print(r.success, r.delta_wns, len(r.candidate_outputs()))
print(round(calculate_fmax(-1.0, 5.0), 2),
      round(calculate_fmax(-0.7, 5.0), 2))
'@ | python -B -

预期输出：

{'directive': 'Explore'}
[['u0/Q', 'u1/I0'], ['u1/I0', 'u1/O'], ['u1/O', 'u2/D']]
True -0.1 1
166.67 175.44

第三行 success 为 True，delta 却为负，且返回了一个候选描述。它不代表有收益，也不代表 demo.dcp 存在。把 success 改成 False，保持显式 candidates 为空，观察输出数量。

合上正文，做六道自测

为什么 phys_opt 成功也可能没有提升？

成功描述执行和产物；该技能没有把 delta_wns > 0 作为成功必要条件。收益与接纳由后续测量评估决定。

局部重布线为什么反复打开 input_dcp？

让不同窗口从同一份输入出发，避免把上个候选的修改累积到下个候选。操作范围仍要看 route_mode。

LUT 的 I2 和 A6 有何区别？

I2 是逻辑输入，A6 是物理 BEL 输入。交换调整映射和相应物理连接，不能理解为随意交换逻辑信号。

output_dcp 就是代理会测的唯一文件吗？

不是。显式 candidates 非空时，candidate_outputs() 优先使用它；当前 auto 扫描只将第一轮局部合法输出加入列表。

为什么不用 SkillResult.after_wns 直接排最终名次？

它是技能内某个时刻的观测。代理要重开规范保存的候选，在统一入口测量并检查完整性与合法性。

集中测量一定比较参考 DCP 的约束吗？

只有传入 reference_dcp_path 的分支在这里比较两份 DCP 的时钟与 timing XDC；需检查具体调用点。
